## What the behaviour actually is

Reproduced against the real seal before anything was written:

| Seeded state | Result |
|---|---|
| a partition id absent from the manifest | `FAIL[ORIGINAL_PARTITION_UNAVAILABLE]`, naming the id and `NOT_IN_MANIFEST` |
| `[]`, `None`, `()` | `FAIL[NO_RECORDED_PARTITIONS]` — an empty list is a missing record, not an empty input set |
| `'injuries'`, `''`, `None`, `'no-at-sign'`, `'@abc'`, `123` | `PARTITION_ID_MALFORMED` for each, including the empty-source case |
| the seal's 7 real ids | all 7 resolve to the **recorded** content, zero mismatches |

And the negative fixture holds **on live data rather than a synthetic**: every
one of the seven sealed sources has newer observations in the manifest — 20, 648,
14, 367, 574, 346 and 19 respectively — and the pinned build took the recorded
hash for all seven.

## The premise is asserted, not assumed

Criterion 7 is only a test while the manifest holds newer observations of the
sealed sources. If it stopped growing, "replay consumed A only" would be true by
having nothing else to choose, and the file would pass while measuring nothing.

and fails loudly if it disappears. The sibling test already names this trap for
the digest check — *"if this reads AGREES_TODAY the manifest has stopped growing
and the defect is dormant, which is not the same as fixed."*
