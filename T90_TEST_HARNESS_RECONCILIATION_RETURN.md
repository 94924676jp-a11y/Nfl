## 7. EXECUTION DEFECT 2 — the inactives page was passing its own control by accident

The source of the FAIL above:

    FAIL   HTML_SHELL_OR_EMPTY   official_inactives

`capture_vintage.py` applied **one shared marker set** — `questionable`,
`doubtful`, `did not participate`, `limited participation`, `full
participation` — to **every** html source. Those are the *injury report's*
words. Measured on the committed inactives blobs:

| marker | count on the inactives page |
|---|---|
| `inactive` | **21** |
| `questionable` | 4 |
| `doubtful`, `did not participate`, `limited participation`, `full participation` | **0** |

The inactives page was passing on **four incidental `questionable`s**, while
the word that actually describes its content was not in the marker list at
all. When those four dropped off the page at 17:36Z the control flipped to
FAIL over **419KB of fully-rendered real content**.

This sits directly on the G0A discharge path: the T−90 inactives capture was
being judged by vocabulary its own page does not use.

**Fixed, and the fix makes it stricter, not looser:**

1. `SourceSpec.content_markers` — each source is judged by **its own** subject
   vocabulary. `official_inactives` now requires `inactive`; the injury report
   keeps the participation words.
2. **A shell and an unpublished page are now different facts.** A tiny payload
   or a JS-shell marker stays **FAIL** — the page did not render. A
   fully-rendered page carrying none of its own markers is
   **`DEFERRED / SOURCE_HAS_NO_ROWS_YET`**, the same state the 404 sources
   report. Nothing is stored, nothing is discharged, and it stays **owed**.

The old behaviour called an unpublished page a defect, failed the run, and —
because of §6 — discarded six other sources' evidence for it.

## 8. Test-design ruling (§5)

The assertion `"no window has closed"` was **an invalid test design using
wall-clock-dependent expectations** — option 1 — repaired as **option 3**, a
time-aware state transition.

What those assertions were protecting is time-invariant: *the live manifest
must never falsely cover anything.* The specific values (`missed == 0`,
`not_yet_due == n_targets`, the DEFERRED branch's wording) were merely what
that meaning looked like on 2026-09-07.

Replaced with, derived from the coverage contract rather than from the
examples in the packet:

- the state is **never PASS** while nothing is genuinely covered;
- the state **matches the calendar** — `DEFERRED[NO_WINDOW_HAS_CLOSED_YET]`
  with `missed == 0` before any window closes, `FAIL[PERISHABLE_WINDOWS_MISSED]`
  with `missed > 0` once one closes unfilled;
- `covered + missed + not_yet_due == n_targets` **exactly**;
- a real future obligation remains;
- the refusal names the game-level fact on **whichever branch** the calendar
  puts us in.

`covered == 0` and `attributed_captures == 0` are unchanged and still assert
the original defect stays fixed.

I did **not** mechanically add `test_zz` to 26 files. I first asked whether the

Audit of all 33 discovered modules: **0 import-time checks, 0 vacuous modules,

count with variables named **`P` and `F`**. `run_suite.tally()` looked for

three files, one commit after writing it.

tally-backed, 0 exception-only, 0 unobserved.**

A second, subtler defect in my own audit: it first computed "is this module
tally-backed?" from **its own hardcoded copy** of the tally list, so it would
have certified a capability the runner lacked. It now reads
`run_suite.tally()` directly. A test about a runner must use the runner.

### Seeded-failure proofs, against the real runner (§7)

`--only <substr>` was added to the runner so a seeded module can be proven
without a full run. It changes discovery only, never judgement.

| seeded style | runner exits non-zero | prints `SUITE FAIL` | names the module | seed removed |
|---|---|---|---|---|
| tally-backed failing check | ✓ | ✓ | ✓ | ✓ |
| exception-only (`assert False`) | ✓ | ✓ | ✓ | ✓ |
| vacuous (zero checks recorded) | ✓ | ✓ | ✓ | ✓ |
| **clean control module** | **exits 0, `SUITE PASS`** | — | — | ✓ |

The clean control matters: a runner that is always red proves nothing. Every
