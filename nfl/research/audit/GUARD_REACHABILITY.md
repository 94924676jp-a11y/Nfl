**The fifth class is the correction that mattered, and leaving it out made the
first version of this census a false accusation against working governance.**
`nfl/production/verdict.py` is a verdict registry *with enforcement*:
`from_outcome` maps a governance Outcome onto a gate result, `CLEARING` is
`('PASS',)` alone, and `assess()` refuses a scope when any required gate is not
clearing — with a gate *absent* from the dict counted `NOT_EVALUATED`, never
assumed passing. 23 gates are registered; 18 are required for the `football`
scope.

So in `universe/run_chain.py` the calling line only *stores* the Outcome, and
the enforcement is a separate statement:

```python
inact = CV.assert_no_inactive_survives(...)
L['inactive_application'] = {...}                    # what a per-site rule sees
G['INACTIVE_APPLICATION'] = V.from_outcome(inact)    # what actually enforces it
```

Five guards read as `ANNOTATE` until the tool followed that, and two of them
only after following one `.append()` hop into an aggregate. They are wired to
`INACTIVE_APPLICATION`, `ROLE_PLAUSIBILITY`, `PARTICIPATION_COMPLETENESS`,
`OPPORTUNITY_CONSERVATION` and `REDISTRIBUTION_PLAUSIBILITY`. Only **one** hop
is followed on purpose: a wrong `LOAD_BEARING` is worse than an honest
`NOT_ESTABLISHED`.

A second correction, caught by the tool against its own author: a guard that
**raises** on failure is a STOP even when called as a bare statement, because
the raise *is* the stop and the return value is the success value. The first
rule only said so for guards that never returned anything, and therefore
misclassified `assert_graded_row` — which raises `AnonymousZero` and returns a
provenance block — as `NOTHING`.

## What this tool does NOT decide

It cannot separate an `ORPHANED_CONTROL` from a deliberate `ADVISORY` one:
that is intent, and intent is not in the syntax. Every row therefore carries
`classification: NOT_ESTABLISHED` until a human writes one, and no row here
should be read as a verdict that a guard *ought* to be called.
